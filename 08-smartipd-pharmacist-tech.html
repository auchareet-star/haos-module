08 · Smart IPD — Pharmacist Module

โมดูลเภสัชกรเป็นโมดูลที่ถูก แยกออกจากส่วนอื่นอย่างชัดเจน — ผู้ใช้ role Pharmacist จะถูก guard บังคับให้อยู่ใน /pharmacist/* เท่านั้น งานหลักคือเดินใบสั่งยา IPD ผ่านสถานะ 5 ขั้น (รอคัดกรอง → รอจัดยา → รอตรวจสอบ → รอจ่าย → จ่ายแล้ว) พร้อมการตรวจสอบซ้ำ 2 ชั้นสำหรับยา High Alert

Role: Pharmacist (HA.OS UserType = P) Permission: PHARMACIST, MEDICATION_DISPENSING, PHARMACY_MANAGEMENT, DRUG_INVENTORY Root: /pharmacist

สถานะใบสั่งยา 5 ขั้น (+ 3 สถานะพิเศษ)

  • Wรอคัดกรอง
  • Pรอจัดยา
  • Vรอตรวจสอบยา
  • Rรอจ่ายยา
  • Dจ่ายแล้ว
รหัสชื่อความหมายใครทำ
WGรอ GenerateOrder ต่อเนื่องที่ยังไม่ถูกสร้างใบสั่งของวันนี้ระบบ / เภสัชกรกด Generate
RFคำขอเติมยาRefill จาก Wardพยาบาล
Wรอคัดกรองใบสั่งเข้ามาแล้ว รอเภสัชกรคัดกรองความเหมาะสมเภสัชกร
Pรอจัดยาคัดกรองผ่าน รอหยิบ/จัดยาเภสัชกร/ผู้ช่วย
Vรอตรวจสอบยาจัดยาเสร็จ รอตรวจสอบก่อนจ่ายเภสัชกร
Rรอจ่ายยาตรวจสอบผ่าน รอส่งขึ้น Wardเภสัชกร
Dจ่ายแล้วจ่ายเรียบร้อยเภสัชกร
Cยกเลิกใบสั่งถูกยกเลิกเภสัชกร

นิยามอยู่ที่ STATUS_CODES ใน features/pharmacist/models/pharmacist.types.ts (มีสีประจำสถานะกำกับด้วย)

ขั้นที่ 1 — Login & เลือกห้องยา

  1. Login

    /auth/login — ระบบ map UserType = 'P' ของ HA.OS เป็น role Pharmacist

  2. ถูก redirect เข้าโมดูลเภสัช

    roleRedirectGuard อนุญาตให้เภสัชกรเข้าได้เฉพาะ /pharmacist/* และ /home — เส้นทางอื่นจะถูกส่งกลับมาที่ /pharmacist

  3. เลือกห้องยา

    /auth/pharmacy-room-selection — บังคับโดย pharmacyRoomSelectionGuard ทุก route ในโมดูลนี้ · ระบบจำห้องล่าสุดไว้ใน RememberedAccount.lastSelectedPharmacyRoomCode

    เปลี่ยนห้องได้จากการ์ดข้อมูลห้องยาบนหัวหน้าจอ

  4. เข้าหน้าเริ่มต้น

    /pharmacist redirect ไป /pharmacist/ipd-new-order

ขั้นที่ 2 — IPD New Order (จอทำงานหลัก)

/pharmacist/ipd-new-order · IpdNewOrderComponent

2.1 มุมมองแบบสรุปรายผู้ป่วย (แนะนำ)

GET /api/PharmacistDispensing/pending-patient-summary

  • คืนผลแบบแบ่งหน้า 10 ผู้ป่วยต่อหน้า (ไม่ใช่ 10 รายการ) เพื่อลดข้อมูลที่ต้องโหลด
  • แต่ละแถวสรุป: จำนวน Order ทั้งหมด, วันที่ Order ล่าสุด, ธงประเภท Order
  • กรองได้ตาม สถานะ · Ward · แพทย์ · คำค้น (ชื่อผู้ป่วย/HN/AN/ชื่อยา)

2.2 มุมมองรายการเต็ม

GET /api/PharmacistDispensing/pending — พารามิเตอร์ที่ใช้กรอง

Query paramความหมาย
requestDateวันที่ของใบสั่ง (ค่าเริ่มต้น = วันนี้)
wardWorkIdกรองตามหอผู้ป่วย
admitId / anกรองผู้ป่วยรายคน (admitId มีลำดับความสำคัญสูงกว่า)
statusW / P / V / R / D
isHomeMedเอาเฉพาะยากลับบ้าน
generatedByกรองตามผู้/ระบบที่สร้างใบสั่ง

Response มี ตัวนับแยกตามสถานะ มาด้วย ใช้ทำชิปกรองด้านบน · endpoint นี้เปิดให้ Doctor/Nurse/Pharmacist เรียกดูได้ (RequireRole 3 บทบาท)

2.3 เข้าดูผู้ป่วยรายคน

/pharmacist/patient-order · PharmacistPatientOrderComponent — รายการยาทั้งหมดของผู้ป่วย พร้อมธงเตือน · เข้าได้จากการคลิกในตาราง หรือ สแกน QR ที่ /pharmacist/scan

ขั้นที่ 3 — Generate Order รายวัน

/pharmacist/ipd-generate-order · IpdGenerateOrderComponent · API POST /api/PharmacistDispensing/generate-daily?requestDate=

  1. เลือกวันที่

    ค่าเริ่มต้นคือวันนี้ — ใช้ย้อนหลังได้กรณีวันก่อนหน้าไม่ถูก generate

  2. กด Generate

    ระบบสร้างใบสั่งจ่ายยาสถานะ WG (WaitingGenerate) สำหรับ Order ประเภท Continue ที่ต่อเนื่องจากวันก่อน

  3. ตรวจผลลัพธ์

    API คืน GenerateDailyDispensingResultDto ที่บอกจำนวน ที่สร้างใหม่ และ ที่มีอยู่แล้ว — ใช้ตรวจว่ากด Generate ซ้ำหรือไม่

ทำไมต้อง Generate

Order ประเภท OneDay เกิดใบสั่งจ่ายทันทีที่แพทย์สั่ง แต่ Continue เป็นคำสั่งต่อเนื่องที่ต้อง “แตกเป็นใบสั่งของแต่ละวัน” — ขั้นตอนนี้คือการแตกใบสั่งของวันนั้น

ขั้นที่ 4 — เดินสถานะใบสั่ง

API เดียวใช้เดินทุกสถานะ: PUT /api/PharmacistDispensing/status (RequireRole(Pharmacist) เท่านั้น)

// body
{
  "dispensingRequestIds": [ 1001, 1002, 1003 ],   // อัปเดตทีละหลายใบได้
  "newStatus": "Verified"                          // Waiting | Pending | Verified | Ready | Dispensed
}
ขั้นสิ่งที่เภสัชกรทำnewStatusสถานะผลลัพธ์
1คัดกรองใบสั่ง — ตรวจธงเตือน, ขนาดยา, ความเหมาะสมPendingP
2จัดยาตามใบสั่งVerifiedV
3ตรวจสอบยาที่จัดแล้ว (+ Verification ถ้าเป็น HAD)ReadyR
4ส่งยาขึ้น WardDispensedD
ทำงานเป็นชุด

dispensingRequestIds เป็น array — หน้า “จัดการแบบกลุ่ม” ใช้ความสามารถนี้ เพื่อเดินสถานะหลายใบพร้อมกัน

ขั้นที่ 5 — ธงเตือนที่ต้องตรวจ

ทุกบรรทัดยาที่เภสัชกรเห็นมาพร้อมธงเตือนที่ระบบตรวจให้ตั้งแต่ตอนแพทย์สั่ง (POST /api/MedicationOrder/validate) และแต่ละธงมีข้อความอธิบายของตัวเอง

ธงข้อความประกอบเภสัชกรต้องทำอะไร
isDrugAllergydrugAllergyMessageตรวจประวัติแพ้ยา — ถ้าจริงต้องติดต่อแพทย์
isDuplicateDrugduplicateDrugMessageตรวจว่าซ้ำจริงหรือเป็นการปรับขนาด
isDrugDrugInteractiondrugDrugInteractionMessageประเมินระดับความรุนแรง
isDrugDiseaseInteractiondrugDiseaseInteractionMessageเทียบกับโรคประจำตัว
isDrugLabInteractiondrugLabInteractionMessageดูผล Lab ล่าสุด (เช่น ค่าไต)
isNonEssentialDrugnonEssentialDrugMessageยานอกบัญชี — ตรวจการอนุมัติ/เบิกจ่าย
isFormDueformDueMessage + dueAnswerListอ่านคำตอบ DUE ที่แพทย์กรอกมา แล้วประเมิน

ดูคำตอบ DUE ของแพทย์

ถ้ารายการมี dueTemplateId ให้โหลดโครงคำถามด้วย GET /api/Medication/due-templates/{dueTemplateId} แล้วนำมาแสดงคู่กับ dueAnswerList ที่แพทย์กรอกไว้ตอนสั่ง

ขั้นที่ 6 — Verification 2 ชั้น สำหรับยา High Alert (HAD)

ยา High Alert ต้องมีเภสัชกรคนที่ 2 ยืนยัน — ระบบบันทึกทั้งคนแรกและ secondReviewerId/secondReviewerName

  1. ดูรายชื่อเภสัชกรที่เป็นผู้ตรวจสอบได้

    GET /api/PharmacistDispensing/verification/pharmacists

  2. ผู้ตรวจสอบคนที่ 2 ยืนยันตัวตนด้วยรหัสผ่าน

    POST /api/PharmacistDispensing/verification/verify-password — ส่ง userId + password ระบบคืนผลว่าผ่านหรือไม่ (ไม่ต้อง logout/login สลับบัญชี)

  3. บันทึกการตรวจสอบ

    POST /api/PharmacistDispensing/verification — รองรับทั้งใบเดียวและแบบชุด คืน SaveVerificationResponseDto พร้อม verification ID

  4. ดูประวัติการตรวจสอบ

    ใบเดียว: GET /api/PharmacistDispensing/verification/{dispensingRequestId}
    หลายใบพร้อมกัน: POST /api/PharmacistDispensing/verification/batch

ขั้นที่ 7 — Hold / Off / ยกเลิก

เมื่อแพทย์สั่งพักหรือหยุดยา เภสัชกรต้อง กดรับทราบ เพื่อให้ระบบรู้ว่ามีคนเห็นแล้ว

สถานการณ์ธงที่เห็นAPI ที่ต้องเรียกบันทึกอะไร
แพทย์สั่ง Hold (พักชั่วคราว) isOnHold + holdOrderReason POST /api/PharmacistDispensing/acknowledge-hold isHoldAcknowledged = true
แพทย์สั่ง Off (หยุดยา) isOff + offOrderDate + offOrderReason POST /api/PharmacistDispensing/acknowledge-off isOffAcknowledged, offAcknowledgedBy, offAcknowledgedAt
ต้องยกเลิกใบสั่งจ่าย — POST /api/PharmacistDispensing/cancel-dispensing-request สถานะ C

แหล่งข้อมูล: TB_IPD_ORDER_HOLD_LOGS (Hold) และ TB_IPD_ORDER_NOTE_DETAILS (Off) ฝั่ง HA.OS — พยาบาลจะเห็น badge เดียวกันบนหน้า eMAR (โมดูล 06)

จัดการแบบกลุ่ม & พิมพ์ Sticker

  • เลือกใบสั่งหลายใบแล้วเดินสถานะพร้อมกัน (PUT /status กับ array ของ ID)
  • พิมพ์ฉลากยาเป็นชุด — POST /api/Medication/generate-label

ดูรูปผู้ป่วย

Home Med (ยากลับบ้าน)

/pharmacist/ipd-home-med-order · IpdHomeMedOrderComponent

  • กรองด้วย isHomeMed=true ที่ GET /pending

  • เดินสถานะเหมือนใบสั่งปกติ แต่มักต้องทำคู่กับ Med Reconcile Discharge และการให้คำแนะนำผู้ป่วย

ข้อควรระวัง

1. ไม่เลือกห้องยา = เข้าไม่ได้

ทุก route ในโมดูลมี pharmacyRoomSelectionGuard — ถ้าเด้งกลับหน้าเลือกห้องซ้ำ ๆ ให้ตรวจว่าห้องยาถูกตั้งค่าไว้ใน master data ของ HA.OS หรือยัง

2. เภสัชกรออกจากโมดูลไม่ได้

roleRedirectGuard บังคับ — ถ้าเภสัชกรต้องใช้หน้าจออื่น ต้องแก้ที่ระดับ role/permission ไม่ใช่ที่ URL

3. Generate ซ้ำไม่สร้างซ้ำ

API คืนจำนวน “มีอยู่แล้ว” แยกจาก “สร้างใหม่” ให้ดูตัวเลขนี้แทนการเดา

4. ธงเตือนเป็นข้อมูลจากตอนแพทย์สั่ง

ถ้าสถานะผู้ป่วยเปลี่ยนหลังจากนั้น (เช่นผล Lab ใหม่) ธงอาจยังไม่อัปเดต — ควรตรวจผล Lab ล่าสุดประกอบด้วย

5. Hold/Off ที่ยังไม่รับทราบ

ถ้าเภสัชกรไม่กดรับทราบ พยาบาลจะเห็น badge ค้างบน eMAR และอาจเกิดความสับสนว่าตกลงให้ยาได้หรือไม่

6. อย่าลืมพิมพ์ฉลาก

printStickerDialogGuard จะเตือนตอนออกจากหน้า — ถ้ากดข้ามไป ยาอาจถูกส่งขึ้น Ward โดยไม่มีฉลาก
