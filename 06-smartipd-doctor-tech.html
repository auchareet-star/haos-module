06 · Smart IPD — Doctor Module

Smart IPD คือแอปแยกต่างหาก (Angular 19 standalone + .NET 9) ที่ออกแบบให้แพทย์ใช้บน tablet ข้างเตียง ตัว backend ทำหน้าที่เป็น BFF (Backend for Frontend) — ไม่มีฐานข้อมูลเวชระเบียนของตัวเอง แต่เรียกต่อไปยัง HA.OS WebAPI ผ่าน Kiota-generated client แล้วจัดรูปข้อมูลให้เหมาะกับหน้าจอ

ขั้นที่ 1 — Login & เลือก Ward

  1. เข้าหน้า Login

    /auth/login · POST /api/Auth/login — ใช้ username/password เดียวกับ HA.OS (ระบบไปยืนยันกับ HA.OS แล้วออก JWT ของ Smart IPD เอง)

    มีฟีเจอร์ “จำบัญชี” (RememberedAccountsService) ซึ่งจำ Ward/ห้องยาที่เลือกล่าสุดด้วย

  2. ระบบ map บทบาทจาก UserType ของ HA.OS
    HA.OS UserTypeSmart IPD Roleเข้าโมดูล
    M แพทย์ · D ทันตแพทย์ · E แพทย์ภายนอกDoctor/patients/doctor-patients
    N พยาบาลNurse/patients
    P เภสัชกรPharmacist/pharmacist (ถูกบังคับ redirect)
    อื่น ๆUserสิทธิจำกัด

    โค้ด: UserTypeMapper.MapHaosUserTypeToRole() และ roleRedirectGuard

  3. เลือก Ward

    /auth/ward-selection — บังคับโดย wardSelectionGuard ทุกหน้าจอหลังจากนี้จะกรองข้อมูลตาม Ward ที่เลือก เปลี่ยน Ward ได้ตลอดจากแถบด้านบน

ขั้นที่ 6 — สั่งยา (Medication Order)

เป็นส่วนที่ซับซ้อนที่สุดของ Doctor Module เพราะมีการตรวจสอบความปลอดภัยหลายชั้น

  1. เปิดหน้ารายการยา

    admission/:an/medication-order?type={OneDay|Continue|HomeMed}

  2. ค้นหายา

    GET /api/Medication/search หรือ search-advanced · ดูรายละเอียด GET /api/Medication/{drugCode} · หมวดหมู่/บัญชียา categories, formularies

  3. ใช้สูตร/Template ช่วย

    admission/:an/medication-templates · GET /api/Medication/templates · templates/{id}/detail · drug-formulas · favorites

  4. กรอกรายละเอียดการสั่ง

    admission/:an/medication-order/add — ขนาด, วิธีใช้, ความถี่, ระยะเวลา, หมายเหตุ

  5. ระบบตรวจสอบความปลอดภัยอัตโนมัติ

    POST /api/MedicationOrder/validate — คืนธงเตือนหลายชนิด

    ธงเตือนความหมาย
    isDrugAllergyผู้ป่วยแพ้ยานี้
    isDuplicateDrugยาซ้ำกับที่สั่งอยู่
    isDrugDrugInteractionปฏิกิริยาระหว่างยา · GET /api/Medication/{drugCode}/interactions
    isDrugDiseaseInteractionปฏิกิริยายา-โรค
    isDrugLabInteractionปฏิกิริยายา-ผล Lab
    isNonEssentialDrugยานอกบัญชี (NED)
    isFormDueต้องกรอกแบบฟอร์ม DUE ก่อนสั่ง
  6. กรอกฟอร์ม DUE (ถ้าถูกร้องขอ)

    GET /api/Medication/due-templates/{dueTemplateId} — คำตอบจะถูกส่งไปกับ order และเภสัชกรจะเห็นคำตอบชุดนี้ตอนตรวจสอบ (dueAnswerList)

    มีเงื่อนไขการสั่งเฉพาะยาบางตัว: GET /api/Medication/{drugCode}/prescribing-conditions

  7. ยืนยันสั่ง

    POST /api/MedicationOrder (แก้ไข PUT /{orderId} · ยกเลิก DELETE /{orderId})

  8. ติดตามผล

    GET /api/MedicationOrder/history · GET /api/MedicationOrder/{patientId}/dispensing-history · หน้า admission/:an/medication-review (Med Review) และ admission/:an/order-history

Hold / Off ยา

แพทย์สามารถสั่ง Hold (พักการให้ยาชั่วคราว) หรือ Off (หยุดยา) ได้ ข้อมูลถูกเก็บที่ TB_IPD_ORDER_HOLD_LOGS และ TB_IPD_ORDER_NOTE_DETAILS ฝั่งเภสัชกรจะเห็นธง isOnHold / isOff พร้อมเหตุผล และต้องกด “รับทราบ” (ดู โมดูล 07)

ข้อควรระวัง

1. Smart IPD ไม่ใช่แหล่งข้อมูลจริง

ข้อมูลทั้งหมดอยู่ที่ HA.OS — ถ้า HA.OS API ล่มหรือ contract เปลี่ยน Smart IPD จะพังทันที ตรวจ log ของ HaosApiClient (ตั้ง LogLevel เป็น Debug ไว้แล้วใน config)

2. UserType ต้องถูกตั้งที่ HA.OS

ถ้าแพทย์ถูกตั้ง UserType เป็นค่าอื่น จะได้ role User และเห็นหน้าจอไม่ครบ แก้ที่เมนูผู้ดูแลระบบของ HA.OS

3. Ward selection มีผลกับทุกหน้าจอ

รายการผู้ป่วยถูกกรองด้วย Ward ที่เลือก ถ้าหาผู้ป่วยไม่เจอให้ตรวจว่าเลือก Ward ถูกหรือยัง

4. Order type ส่งผ่าน query param

เข้าหน้า medication-order โดยตรงโดยไม่มี ?type= อาจได้พฤติกรรมไม่ตรงกับที่ตั้งใจ — ควรเข้าจากเมนู New Order เสมอ

5. Validate ไม่บังคับหยุด

ธงเตือนส่วนใหญ่เป็น “เตือน” ไม่ใช่ “ห้าม” — ยกเว้น DUE ที่ต้องกรอกก่อน การตัดสินใจอยู่ที่แพทย์และจะถูกส่งต่อให้เภสัชกรตรวจซ้ำ

6. เอกสาร spec ในรีโป

ดูรายละเอียดเพิ่มที่ docs/SmartIPD-API-Spec.html, docs/SmartIPD-HIS-Integration-Spec.html และ docs/SmartIPD-HIS-Provider-API.openapi.yaml
