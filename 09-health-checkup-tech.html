09 · ห้องตรวจสุขภาพ (Health Check-up)

ระบบตรวจสุขภาพเป็นแอปแยก (Angular + PrimeNG) ที่มี backend ของตัวเอง (HAOS.HealthCheckup.*) วางคู่กับ HA.OS ในโซลูชันเดียวกัน รองรับทั้งการตรวจ รายบุคคล (Walk-in) และ รายกลุ่มตามโครงการ (เชิงรุก / เชิงรับ) โดยหัวใจของ Flow คือแนวคิด Station — ผู้ป่วยเดินผ่านจุดตรวจทีละจุดจนครบ

ค่าที่ระบบใช้แปลผล Vital Sign

Weight, Height, BMI, Systolic Blood Pressure, Diastolic Blood Pressure, Pulse, Oxygen Saturation (SpO2), Temperature — ผลการแปลออกมาเป็น normal warning abnormal pending

ขั้นที่ 3 — สั่ง Package

3.1 รายบุคคล

/health-checkup/order-package/single

  1. ค้นผู้รับบริการ

    ถ้าเคยมีประวัติ → /order-package/single/:id (SingleOrderOfPatientComponent)
    ถ้าเป็นคนใหม่ → /order-package/single/new-patient (SingleOrderOfNewPatientComponent)

    API: GET /api/Package/single-order-patient?patientId=&serviceId=&serviceDate=

  2. ตรวจว่ามี Service ของวันนั้นแล้วหรือยัง

    GET /api/Package/check-service-exist?hcPatientId=&serviceDate= — กันสั่งซ้ำ

  3. เลือก Package + ปรับรายการ

    เพิ่ม/ลดรายการตรวจจากแพ็กเกจมาตรฐานได้ · ระบบคำนวณค่าใช้จ่ายให้ (expense-summary-dialog)

  4. ยืนยันสั่ง

    POST /api/Package/order-single-package — สร้าง TbHealthCheckupService และ Checklist ของแต่ละ Station

3.2 รายกลุ่ม

/health-checkup/order-package/group/list/{proactive|defensive} → /order-package/group/manage-package

  1. เลือกโครงการ

    GET /api/Package/group-order-activity

  2. ดูรายชื่อผู้เข้าร่วม

    GET /api/Package/group-order-patients/{activityId}

  3. จัดการรายชื่อ

    POST/PUT/DELETE /api/Package/group-order-patients/{activityId} · นำเข้า Excel: POST /api/Package/group-order-patients-from-excel/{activityId}

  4. สั่ง Package ให้ทั้งกลุ่ม (Mass Order)

    POST /api/Package/mass-order-package — ถ้ามีผู้ที่สิทธิไม่ผ่านจะขึ้น invalid-patients-privilege-dialog ให้ตรวจก่อน

  5. ตรวจสอบสถานะการสั่ง

    /health-checkup/order-package/order-status → /order-status/:hcActivityId (OrderPatientStatusComponent)

เมนูเชิงรับมีหน้าเฉพาะเพิ่ม: /order-package/group/defensive-order (DefensiveOrderComponent) · การยกเลิก/ลบแพ็กเกจใช้ dialog cancel-package-dialog / delete-package-dialog

ขั้นที่ 5 — Checklist Station (หัวใจของงานหน้างาน)

นี่คือหน้าจอที่เจ้าหน้าที่ประจำแต่ละจุดตรวจใช้จริงในวันตรวจ

5.1 เส้นทาง

โหมดรายชื่อผู้ป่วยที่จุดตรวจหน้าบันทึกรายคน
รายบุคคล/checklist/single/:station /checklist/single/service/:hcServiceId/:station/patient/:hcPatientId
รายกลุ่ม/checklist/activity/:type → /checklist/activity/:type/:hcActivityId/:station /checklist/activity/:hcActivityId/:station/patient/:hcPatientId

5.2 ขั้นตอนที่จุดตรวจ

  1. เลือกจุดตรวจของตัวเอง

    เจ้าหน้าที่เปิดหน้า Station ที่ตนประจำ (เช่น vital-sign) ระบบแสดงเฉพาะผู้ที่ยังไม่ผ่านจุดนี้

    API: GET /api/Checklist/checklist-activity-detail (กลุ่ม) · GET /api/Checklist/checklist-individual (เดี่ยว)

  2. เรียกผู้รับบริการ

    ค้นด้วยชื่อ/HN หรือสแกน · ดูสถานะรวมทุกจุดของคนนั้นได้ที่ GET /api/Checklist/checklist-patient-status

  3. บันทึกผลตามจุดตรวจ
    StationComponentAPI บันทึก
    Vital Signchecklist-vital-signPOST /api/Checklist/save-patient-vital-sign-station
    Labchecklist-labPOST /api/Checklist/save-patient-examine-station
    X-raychecklist-x-ray
    Service / Orderchecklist-order

    อ่านค่าเดิม: GET /api/Checklist/get-patient-vital-sign-station · GET /api/Checklist/get-patient-examine-station

  4. อัปเดตสถานะผ่านจุดตรวจ

    POST /api/Checklist/update-patient-check-status → Done หรือ Cancel

  5. ส่งต่อไปจุดถัดไป

    ปุ่ม “เปลี่ยนจุดตรวจ” (checklist-change-station + checklist-change-station-dialog) จะ navigate ไป Station ถัดไปของผู้ป่วยคนเดิม โดยคงบริบท hcActivityId/hcServiceId ไว้

5.3 เอกสารที่พิมพ์ได้จากจุดตรวจ

  1. ดู Dashboard ห้องตรวจ

ข้อควรระวัง

1. Station ต้องถูกกำหนดตั้งแต่ตอนทำ Package

ถ้ารายการตรวจไม่ผูก Station ผู้รับบริการจะไม่ปรากฏที่จุดตรวจนั้น

2. Lab Mapping ไม่ครบ = ผลไม่ขึ้น

ต้อง map รหัส Lab ของ HA.OS เข้ากลุ่ม Lab ตรวจสุขภาพก่อน มิฉะนั้นผลที่ import มาจะจับคู่ไม่ได้

3. เกณฑ์ Vital Sign ไม่ตั้ง = แปลผลไม่ได้

ค่าจะขึ้นเป็น pending ทั้งหมด ต้องตั้งที่เมนู “กำหนดค่าการแปลผล Vital Sign” ก่อน

4. สั่ง Package ซ้ำในวันเดียวกัน

ใช้ check-service-exist ตรวจก่อนเสมอ — ระบบสร้าง Service ซ้ำได้ถ้าข้ามขั้นนี้

5. ผู้เข้าร่วมที่เพิ่มทีหลัง

คนที่เพิ่มเข้าโครงการหลัง Mass Order จะไม่มี Checklist — ใช้ init-patient-not-existed-checklist สร้างให้

6. Import Excel ต้องตรง template

ทั้งรายชื่อผู้เข้าร่วมและผลตรวจ ควรดาวน์โหลด template จากระบบและไม่แก้หัวคอลัมน์
