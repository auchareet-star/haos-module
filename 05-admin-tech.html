1. ผู้ใช้งาน · Role · สิทธิ

HA.OS ใช้โมเดลสิทธิ 3 ชั้น

  • Roleชุดสิทธิสำเร็จรูป
  • Userผูก Role + สิทธิเฉพาะตัว
  • Permission Codeตัวคุมเมนู/ปุ่ม

1.1 กำหนด Role

/admin/role-manage · API GET /api/Admin/GetRoleById · POST /api/Admin/AddOrUpdateRole

  1. สร้าง Role ใหม่

    ตั้งชื่อ Role ตามหน้าที่งาน เช่น “เจ้าหน้าที่การเงิน OPD”, “เภสัชกร IPD”

  2. ติ๊กสิทธิที่ Role นี้ได้รับ

    สิทธิเป็นรหัสข้อความ (Permission Code) ที่หน้าจอฝั่ง Angular เอาไปเทียบใน menu.config.ts (คุมการเห็นเมนู) และในแต่ละ component (คุมการเห็นปุ่ม)

    กลุ่มตัวอย่าง Permission Code
    ผู้ดูแลระบบIT_ADMIN, IT_ADMIN_SYSTEM_ERROR_DASHBOARD, IT_ADMIN_CHECK_DATADICTIONARY
    การเงินนอกOUTPATIENT_FINANCE, OUTPATIENT_FINANCE_DASHBOARD, OUTPATIENT_FINANCE_OPD_BILLING, OUTPATIENT_FINANCE_CHECK_CANCEL_BILL
    การเงินในINPATIENT_FINANCE, INPATIENT_FINANCE_LOGIN, INPATIENT_FINANCE_IPD_EXPENSE_SUMMARY
    เรียกเก็บREIMBURSEMENT, REIMBURSEMENT_DASHBOARD, REIMBURSEMENT_REIMBURSE_ROUND, REIMBURSEMENT_REIMBURSE_PAYMENT
    ห้องปฏิบัติการLABORATORY, LABORATORY_MASTER_DATA
    อื่น ๆDOCTOR_CLINIC, APPOINTMENT_APPOINT, OPD_CLINIC, REFER_CENTER
  3. บันทึก

    ผู้ใช้ที่ผูก Role นี้อยู่จะได้รับสิทธิใหม่หลัง login ใหม่

1.2 ลงทะเบียนผู้ใช้งานระบบ

/admin/user-management → /admin/user-create (หรือ /admin/user-create/:id/:EditMode)

  1. กรอกข้อมูลบุคคล

    คำนำหน้า, ชื่อ-สกุล (ไทย/อังกฤษ), แผนก (TBM_DEPARTMENTS), ประเภทผู้ให้บริการ (TBM_PROVIDERTYPES), เลขที่ใบประกอบวิชาชีพ, ธนาคาร/เลขบัญชี

  2. กำหนด User Type

    สำคัญมากเพราะระบบอื่นใช้ค่านี้ตัดสินบทบาท

    UserTypeความหมายบทบาทใน Smart IPD
    Mแพทย์Doctor
    Dทันตแพทย์
    Eแพทย์ภายนอก
    NพยาบาลNurse
    PเภสัชกรPharmacist
    อื่น ๆเจ้าหน้าที่ทั่วไปUser

    อ้างอิง UserTypeMapper.MapHaosUserTypeToRole() ใน Smart IPD — ตั้ง UserType ผิด ผู้ใช้จะเข้าโมดูลผิดใน Smart IPD (ดู โมดูล 05-07)

  3. ตั้ง Username / Password

    เงื่อนไขความยาวและวันหมดอายุมาจาก Parameter MinPassword / PasswordExpire

  4. ผูก Role

    เลือกจาก Role ที่สร้างไว้

  5. กำหนดสถานที่ทำงานที่เข้าถึงได้

    ผูก WorkPlace ที่ผู้ใช้เข้าใช้งานได้ (ใช้กับหน้าจอที่มี WorkGuard)

1.3 กำหนดสิทธิการใช้งานรายบุคคล

/admin/user-rights · /admin/user-rights/:id — ปรับสิทธิเฉพาะรายบุคคลเพิ่มเติมจาก Role (กรณีข้อยกเว้น)

แนวทางที่แนะนำ

ให้ใช้ Role เป็นหลัก และใช้สิทธิรายบุคคลเฉพาะกรณียกเว้นจริง ๆ เพราะสิทธิรายบุคคลกระจัดกระจายและตรวจสอบย้อนหลังยาก

2. Personal Access Token (สำหรับระบบภายนอก)

เป็นกลไกที่ระบบภายนอก (BBIS/LIS, Kiosk-TV, Robot, ระบบ Partner) ใช้เรียก API ของ HA.OS โดยไม่ต้อง login ด้วย username/password — ส่งผ่าน HTTP header PersonalToken

วิธีสร้าง

  1. เข้าหน้าแก้ไขผู้ใช้

    /admin/user-create/:id/:EditMode เลื่อนไปส่วน Personal Access Token

  2. กรอกชื่อ Token + วันหมดอายุ

    ชื่อเป็นเพียงคำอธิบาย · เว้นวันหมดอายุว่าง = ไม่หมดอายุ

  3. กดสร้าง

    POST /api/Admin/CreatePersonalAccessToken — ระบบสร้าง GUID แบบ "N" (32 ตัวอักษร ไม่มีขีด) คืนมาเป็น plain text ครั้งเดียว ผ่าน dialog และเก็บเฉพาะค่า hash ลง TB_PERSONAL_ACCESS_TOKENS.ACCESS_TOKEN

  4. คัดลอกไปตั้งค่าที่ระบบภายนอก

การจัดการ Token

การกระทำAPIผล
ดูรายการGET /api/Admin/GetPersonalAccessTokenByUserIdListแสดงชื่อ, วันที่สร้าง, วันหมดอายุ (ไม่แสดงค่า token)
แก้ไขPOST /api/Admin/UpdatePersonalAccessTokenเปลี่ยนชื่อ/วันหมดอายุ (ค่า token เดิมยังใช้ได้)
RevokePOST /api/Admin/RevokePersonalAccessTokenออกค่าใหม่ ค่าเดิมใช้ไม่ได้ทันที — dialog แสดงค่าใหม่
ลบPOST /api/Admin/DeletePersonalAccessTokenลบถาวร

พฤติกรรมการตรวจสอบ (CustomApiServiceAuthorizeAttribute)

สถานการณ์HTTP Statusความหมาย
Token ถูกต้อง + ยังไม่หมดอายุ200ผ่าน — ระบบตั้ง CredentialPrincipal เป็น user เจ้าของ token
ไม่ส่ง header / token ไม่ตรง / หมดอายุ401ปฏิเสธ
ตรวจสอบล้มเหลว (DB ล่ม, timeout)500ปัญหาฝั่ง server — ไม่ใช่ token หมดอายุ ให้ client retry
Endpoint ที่มี [AllowAnonymous]200ข้ามการตรวจ
ทำไม 500 ไม่ใช่ 401

โค้ดจงใจแยกสองกรณีนี้ เพราะเดิมทีการคืน 401 ตอน DB มีปัญหาชั่วคราว ทำให้ Kiosk-TV ลบ token ที่เก็บไว้ทิ้งและต้องไปกรอกใหม่ที่เครื่อง การคืน 500 ทำให้ client retry แทน

Token ถูกบันทึกลง log แบบ mask (แสดงเฉพาะ 4 ตัวท้าย) เท่านั้น

แนวปฏิบัติ

สร้าง service account แยกต่อระบบภายนอกแต่ละตัว (เช่น svc_bbis, svc_kiosk) เพราะทุกข้อมูลที่ระบบภายนอกสร้าง จะบันทึก UserCreated เป็นเจ้าของ token — ทำให้ตรวจสอบย้อนหลังได้ว่ารายการไหนมาจากระบบใด และ revoke ได้แยกกัน

3. กำหนด Parameter (พารามิเตอร์ระดับโรงพยาบาล)

/admin/hosp-parameter · GET /api/Admin/GetParameterData · POST /api/Admin/ManageParameterData · ตาราง TBM_HOSP_PARAMETERS (1 แถวเท่านั้น)

หน้าจอเดียวนี้คุมพฤติกรรมของทั้งระบบ แบ่งเป็นกลุ่มดังนี้

3.1 ข้อมูลโรงพยาบาล

HospCode, HospName, EName, InitialName, ที่อยู่เต็ม, Latitude/Longitude, SssCode, Careas, เบอร์โทร/Fax/Email/Line/Website, LogoFilename, UrlQrcode, BankAccount

ข้อมูลชุดนี้ขึ้นบนหัวรายงานและใบเสร็จทุกใบ

3.2 ผู้บริหารที่ลงนาม

Hd* (ผู้อำนวยการ), Dhd1*, Dhd2* (รอง 2 คน) — ชื่อไทย/อังกฤษ, ตำแหน่ง, และ UserId ที่ผูกเพื่อดึงลายเซ็นดิจิทัล

3.3 Flag เปิด/ปิดโมดูล (สำคัญที่สุด)

IsDrugCenterEnabledเปิดโมดูลศูนย์ยา

3.5 Lab / X-Ray / PACS

CentralLab, LockAcceptLab, CentralXray, LockAcceptXray, XrayLabLockFlag, PacsInterface, PacsUrl, และ LabMonitors[] (รายการ Lab ที่ต้องเฝ้าติดตาม)

มีคอลัมน์ BbReqPath สำหรับ path ไฟล์ ASTM ของธนาคารเลือดแบบเดิมด้วย

3.6 การพิมพ์ฉลาก

AutoPrintOlabel1..4, AutoCopyOlabel3 (OPD) และ AutoPrintIlabel1..2, AutoCopyIlabel2 (IPD), AutoPrintService — และตรวจข้อยกเว้นรายจุดด้วย GET /api/Admin/CheckWorkPlaceDisabledAutoPrint?workId=

3.7 ความปลอดภัย / บัญชีเชื่อมต่อ

PasswordExpire, MinPassword, และบัญชีสำหรับระบบภายนอก (MophClaimUserName, PHRUserName, NAPPLUSUserName พร้อมรหัสผ่าน)

ระวัง

รหัสผ่านของระบบภายนอกถูกเก็บใน parameter table และปรากฏใน API response ของหน้านี้ จึงควรจำกัดสิทธิ IT_ADMIN ให้แคบที่สุด

3.8 อื่น ๆ

AdvanceVisit + AdvanceVisitDay (เปิด Visit ล่วงหน้า), OverRuleRepeatDrug + OverRuleRepeatDrugDay (ยาซ้ำ), LockDiag / LockDiagIcd / LockDiagPdx (ล็อกการวินิจฉัย), NewBornPrefix (รหัสนำหน้าทารกแรกเกิด), ClearPatientFlag, ViewscanOpd / ViewscanIpd, VersionControl

6. ตั้งค่า Token ตรวจสอบสิทธิ สปสช.

/admin/hosp-nhso-token · Controller NhsoTokenAdminController

  1. ดูสถานะ Token ปัจจุบัน

    GET .../GetStatus — ตรวจว่า token ยังใช้ได้ / ใกล้หมดอายุหรือยัง

  2. ป้อน Token ใหม่

    POST .../SeedToken — วางค่า token ที่ได้จาก สปสช.

  3. หรืออัปโหลดไฟล์ Token

    POST .../UploadTokenFile

เก็บที่ตาราง TB_NHSO_ACCESS_TOKEN (migration 25690715142658_AddTbNhsoAccessToken)

เป็นสาเหตุยอดฮิตของ “ตรวจสิทธิไม่ได้”

Token สปสช. มีอายุจำกัด เมื่อหมดอายุ หน้าตรวจสอบสิทธิและ pipeline ส่งเบิกจะล้มเหลวพร้อมกัน ควรตรวจหน้านี้เป็นงานประจำ

  • ระบบดึงเลขถัดไปผ่าน SequenceHelper.GetSequenceNumber(cSequenceType.…) เช่น SeqGenerateFinanceOrderId, SeqGenerateFinanceAccessionNo
เล่มหมด = ออกใบเสร็จไม่ได้

ข้อควรระวัง

1. Parameter เป็นแถวเดียวทั้งระบบ

TBM_HOSP_PARAMETERS มีแถวเดียว การแก้ค่าจะมีผลกับผู้ใช้ทุกคนทันที ควรทดสอบที่ environment ทดสอบก่อน

2. เปลี่ยนสิทธิต้อง login ใหม่

สิทธิถูก resolve ตอนออก token ผู้ใช้ต้อง logout/login ใหม่จึงจะเห็นเมนูที่เปลี่ยน

3. UserType กำหนดบทบาทข้ามระบบ

ค่า M/D/E/N/P ถูกใช้โดย Smart IPD เพื่อเลือกโมดูล ตั้งผิดจะเข้าโมดูลผิดทันที

4. Token แสดงครั้งเดียว

ทั้ง Personal Access Token และ Revoke — ถ้าไม่ได้คัดลอกไว้ต้อง Revoke เพื่อออกใหม่

5. แก้อัตราสิทธิย้อนหลังไม่กระทบของเก่า

ยอด CREDIT/CASH_RETURN/CASH_NOT_RETURN ถูกคำนวณและบันทึกตอนสร้างรายการ การแก้อัตราจะมีผลกับรายการใหม่เท่านั้น รายการเก่าต้องใช้เมนูปรับยอด/โอนสิทธิ

6. Import Excel ทับข้อมูลเดิม

Import Special Claim Expense/ICD ควรดาวน์โหลด template ล่าสุดทุกครั้ง และตรวจข้อมูลก่อนอัปโหลด
