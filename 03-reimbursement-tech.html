03 · บัญชีลูกหนี้ / งานเรียกเก็บ (Reimbursement)

โมดูล “งานเรียกเก็บ” (เมนู 22) รับช่วงต่อจากงานการเงิน โดยเอายอดส่วนที่ สิทธิ/ต้นสังกัดต้องจ่าย มาตั้งเป็นลูกหนี้ จัดเข้ารอบส่งเบิก ส่งข้อมูลไป สปสช./MOPH Claim/FDH นำเข้าไฟล์ REP & Statement บันทึกรับชำระ และปิดบัญชี — เป็นวงจรที่ยาวที่สุดในระบบและมีขั้นตอนที่ห้ามข้ามอยู่หลายจุด

ทำไมต้อง “ปิดสิทธิ” และ “ปิดบัญชี”

ปิดสิทธิ = ยืนยันว่ารายการค่ารักษาของ Visit/Admit นั้นถูกจับคู่กับสิทธิเรียบร้อยแล้ว ไม่มีการโอนสิทธิเพิ่ม · ปิดบัญชี = ยืนยันว่ายอดลูกหนี้ของงวดนั้นนิ่งแล้ว ไม่มีการเพิ่ม/ลดยอดอีก ทั้งสองอย่างเป็นเงื่อนไขก่อนจะยกเข้ารอบส่งเบิกได้ — รายการที่ยังไม่ปิดจะตกหล่นจากรอบ

ขั้นที่ 1 — สร้างใบเรียกเก็บ (Invoice)

/finance/reimbursement/opd/create-invoice · /finance/reimbursement/ipd/create-invoice · API POST /api/Bill/CreateInvoice · สิทธิ REIMBURSEMENT_OPD_REIMBURSE

  1. ตรวจสอบสิทธิของ Visit/Admit

    /opd/rights (REIMBURSEMENT_CHECK_OPD_RIGHT) หรือ /ipd/rights (REIMBURSEMENT_CHECK_IPD_RIGHT) — ยืนยันสิทธิ, สถานพยาบาลหลัก (Hmain) / รอง (Hsub), และสิทธิย่อยที่ใช้เบิก

  2. ตรวจสรุปค่ารักษา

    /opd/summary · /ipd/summary — ดูรายการที่มียอด CREDIT/REMINBURSE ซึ่งจะยกไปเป็นลูกหนี้ ถ้ายอดไม่ถูกให้ไปแก้ที่ บันทึกปรับยอดเบิกได้ ก่อน

  3. เพิ่มค่าใช้จ่าย Lab/X-Ray/Other ที่ตกหล่น

    /opd/non-drug · /ipd/non-drug — สิทธิ REIMBURSEMENT_*_NON_DRUG_CHARGE

  4. กรอกข้อมูลหัวใบเรียกเก็บ

    ข้อมูลชุดนี้คือสิ่งที่ สปสช./ต้นสังกัดใช้ตรวจสอบ ต้องกรอกให้ครบ

    กลุ่มฟิลด์หมายเหตุ
    สิทธิRightId, OpdRightId/AdmitRightId, Insid, Relinsclสิทธิและความสัมพันธ์ผู้มีสิทธิ
    สถานพยาบาลHmain, Hsub, HmainOpรหัส 5 หลัก
    ประเภทการเคลมClaimtype, Claimcode, IpdClaimCodeดู ตารางรหัส
    อุบัติเหตุ/ฉุกเฉินAetype, Emtype, AeDate, AeCar, AeLitigantเฉพาะเคส AE/EM
    ต้นสังกัด (ข้าราชการ)OwnerName, Govname, Govcode, Ownrightpid, OwnrightPositionเจ้าของสิทธิ + หน่วยงาน
    เอกสารDocumentNo, DocumentDate, BookNo, RunNoเลขที่ใบเรียกเก็บ
    ReferReferno, ReferId, ReferNoOut, ReferHospOut, ReferOutเคสส่งต่อ
    ผ่อนชำระInstallment, InstallmentTerm/Rate/Start/Endกรณีให้ผู้ป่วยผ่อน
    สูติกรรมOPTYPE, GRAVIDA, GA_WEEK, LMP_Date, BIสำหรับเคสคลอด/ADL
    รอบRoundIdถ้าระบุตั้งแต่ตอนสร้างจะเข้ารอบทันที
  5. เลือกรายการค่าใช้จ่ายเข้าใบเรียกเก็บ

    BillGroupList[] — จัดกลุ่มตาม Bill Group ระบบรวมยอด Total, Claim, Copay, Discount ให้เอง และ Payment = Claim − Discount

  6. บันทึก

    สร้างใบเรียกเก็บ BillType = 2 (Charged) พร้อมตั้ง BillStatus เริ่มต้น

Hybrid Invoice

/finance/reimbursement/opd|ipd/hybrid-invoice — สำหรับ Visit/Admit ที่ต้องแยกเรียกเก็บหลายผู้จ่าย (เช่น สิทธิหลัก + ประกัน + ผู้ป่วยจ่ายเอง) สร้างได้หลาย Invoice จาก Service/Admit เดียว

ตรวจสอบ / แก้ไขการเรียกเก็บ

/finance/reimbursement/cancel-invoice · API POST /api/Reimbursement/EditInvoice · สิทธิ REIMBURSEMENT_REIMBURSE_PAYMENT — แก้ไขข้อมูลหัวใบ หรือยกเลิกใบเรียกเก็บ (ยกเลิกได้เฉพาะใบที่ยังไม่รับชำระและยังไม่ปิดรอบ)

ขั้นที่ 2 — ปิดสิทธิ & ปิดบัญชี

2.1 ตรวจสอบรายการที่ยังไม่ปิดสิทธิ

/finance/reimbursement/verify-claim/close-right

  • แสดงรายการที่ยัง “ไม่ปิดสิทธิ” พร้อมยอด เบิกได้ / เบิกไม่ได้
  • ปิดสิทธิได้ทั้งแบบรายการเดียวและแบบเลือกหลายรายการ
  • รายการที่ยังไม่ปิดสิทธิ จะไม่ถูกดึงเข้ารอบส่งเบิก

2.2 การบัญชีผู้ป่วยนอก / ผู้ป่วยใน (ปิดบัญชี)

/finance/reimbursement/close-account-opd · close-account-ipd

  1. ดูรายการที่ยังไม่ปิดบัญชี

    GET /api/Reimbursement/GetNotCloseAccountList

  2. ปิดบัญชี

    เลือกได้ 2 แบบ:

    • PUT /api/Reimbursement/CloseAccountByParams — ปิดตามเงื่อนไขค้นหา (ทั้งชุด)
    • POST /api/Reimbursement/CloseAccountByIdList — ปิดเฉพาะรายการที่เลือก
  3. ตรวจรายการที่ปิดแล้ว

    GET /api/Reimbursement/GetCloseAccountList

  4. ยกเลิกการปิดบัญชี (ถ้าจำเป็น)

    PUT CancelCloseAccountByParams · POST CancelCloseAccountByIdList — ทำได้เฉพาะก่อนที่ใบนั้นจะเข้ารอบส่งเบิกและถูกส่งออกไปแล้ว

ขั้นที่ 3 — รอบส่งเบิก (Bill Round)

3.1 ตรวจสอบรอบก่อนส่งเบิก (Pre-audit)

/finance/reimbursement/pre-audit-bill-rounds · สิทธิ REIMBURSEMENT_REIMBURSE_ROUND

ตรวจความถูกต้องของข้อมูลก่อนปิดรอบ — เป็นด่านสุดท้ายที่ยังแก้ไขได้ง่าย ควรตรวจอย่างน้อย: สิทธิถูกต้อง · Hmain/Hsub ครบ · Claimtype ตรงกับลักษณะการมารับบริการ · รหัสวินิจฉัย/หัตถการครบ · ยอดเบิกได้ไม่เป็นศูนย์โดยไม่ตั้งใจ

3.2 ตรวจสอบรอบส่งเบิก

/finance/reimbursement/bill-rounds — รายการใบเรียกเก็บในรอบ พร้อมยอดรวม เมื่อยืนยันแล้วจึงปิดรอบเพื่อส่งออก

3.3 เปลี่ยนรอบส่งเบิก

/finance/reimbursement/verify-claim/change-disbursement-cycle — ย้ายใบเรียกเก็บจากรอบหนึ่งไปอีกรอบ (เช่น ตกหล่นจากรอบก่อน หรือถูกปฏิเสธแล้วต้องส่งรอบถัดไป)

3.4 บันทึกเลื่อนรอบการเรียกเก็บ (Upload)

/finance/reimbursement/round-upload · สิทธิ REIMBURSEMENT_REIMBURSE_ROUND_CHANGE · API POST /api/Reimbursement/ImportRound — อัปโหลดไฟล์รายการที่จะเลื่อนรอบเป็นชุดใหญ่ และ GET /api/Reimbursement/ExportRound เพื่อดาวน์โหลดผลลัพธ์/แม่แบบ

5.3 ลงบันทึกสถานะข้อมูลเรียกเก็บ (CSCD Upload)

/finance/reimbursement/cscd-upload · สิทธิ REIMBURSEMENT_REIMBURSE_STATUS · API POST /api/Reimbursement/ImportPaymentCscd

อัปโหลดไฟล์สถานะจ่ายเงินกรมบัญชีกลาง (CSCD) เพื่อปรับสถานะรายการ และ GET /api/Reimbursement/ExportReceivedPayment เพื่อดาวน์โหลดผลการนำเข้า

อัตราจ่ายกรมบัญชีกลางกับยอดที่ผู้ป่วยต้องจ่าย

ในหน้าออกใบเสร็จมีตรรกะที่หัก cashNotReturn ตาม cscdRate — ถ้าอัตรา CSCD ในระบบไม่ตรงกับความจริง ยอด “เบิกได้/เบิกไม่ได้” จะเพี้ยนตั้งแต่ต้นทาง ควรตรวจข้อมูลอัตราให้ตรงก่อนเปิดใช้งานจริง

ขั้นที่ 6 — บันทึกรับชำระ & ตัดลูกหนี้

6.1 บันทึกรับชำระเงิน

/finance/reimbursement/receive-payment · สิทธิ REIMBURSEMENT_REIMBURSE_PAYMENT · API POST /api/Reimbursement/CreateReceive

  1. ค้นใบเรียกเก็บที่ต้องรับชำระ

    POST /api/Reimbursement/GetBillInvoiceList

  2. เลือกใบ + ระบุยอดที่ได้รับจริง

    รองรับรับชำระบางส่วน (partial)

  3. บันทึก

    สร้างเอกสาร BillType = 3 (ReceivePayment) และตัดยอดลูกหนี้

  4. กรณีถูกตัดยอด/ปฏิเสธ

    สร้าง BillType = 4 (Discount / ใบลดหนี้) เพื่อล้างส่วนต่าง

Batch & งานอัตโนมัติ

โปรเจกต์ HAOS.Batch (Quartz.NET) รัน Job ที่เกี่ยวกับงานเรียกเก็บดังนี้

JobCron (ค่าตัวอย่าง)ทำอะไร
AutoCreateBillJob0 0 1 * * ? เรียก MophBookingClaimService.JobMophBookingClaim() → FetchCreateInvoice → FetchInvoiceToBookingClaim → FetchSendBookingClaim
MophClaimJob0 0 1 1/1 * ?ส่งข้อมูลเคลมไป MOPH Claim
MophVisitFdhJob0 0 1 * * ?ส่งจำนวน Visit เข้า FDH Data Hub
MophCheckTransJob0 */3 * * * ?ติดตามสถานะ Transaction ที่ FDH ทุก 3 นาที
MophSendPhrJob0 30 0 * * ?ส่งข้อมูล PHR
TransferFinanceBySpecialClaimIcdJob0 0 20 * * ?โอนค่าใช้จ่ายตามเงื่อนไข ICD ที่ตั้งไว้ในเมนู “กำหนดการเรียกเก็บพิเศษ”
กับดักการตั้งค่า Auto Create Bill — ต้องตรวจ 2 ที่ให้ตรงกัน

AutoCreateBillJob ถูก ปลุกด้วย Cron จาก CronBatch:AutoCreateBillJob แต่ภายในตัวมันเองยังตรวจซ้ำอีกชั้นด้วย AutoCreateBillJobSchdule:JobList ซึ่งกำหนดเวลา RunJob ไว้ และจะทำงานก็ต่อเมื่อเวลาปัจจุบันห่างจาก RunJob ไม่เกิน 5 นาที เท่านั้น

ถ้า Cron ตั้งไว้เวลาหนึ่ง (เช่น 01:00) แต่ JobList ระบุ RunJob เป็นเวลาอื่น (เช่น 21:00 และ 00:00) Job จะถูกปลุกขึ้นมาแล้วไม่ทำอะไรเลย — และไม่มี error ให้เห็น ผลคือ ใบเรียกเก็บของทั้งวันไม่ถูกสร้าง เงียบ ๆ

สิ่งที่ควรทำ: ตรวจ log ว่ามีบรรทัด FetchCreateInvoice / Finished FetchSendBookingClaim ขึ้นทุกวันหรือไม่ ถ้าไม่มี ให้ปรับ Cron ให้ตรงกับ RunJob รายการใดรายการหนึ่ง

เรื่องประสิทธิภาพและ Token

Pipeline นี้ประมวลผลทีละรายการและเรียก API ภายนอกต่อรายการ ในวันที่มีผู้ป่วยมากอาจใช้เวลานาน จนทับซ้อนกับรอบถัดไป ([DisallowConcurrentExecution] จะทำให้รอบใหม่ถูกข้าม) และหาก Access Token ของ MOPH/FDH หมดอายุระหว่างรอบ รายการที่เหลือจะกลายเป็น Failed ค้าง — ควรมีการตรวจ backlog ของสถานะ NotSuccess เป็นประจำ และใช้ปุ่ม “ส่งจองเคลมใหม่” ในหน้า Booking Claim เพื่อยิงซ้ำ

ข้อควรระวัง

1. ลำดับที่ห้ามข้าม

Invoice → ปิดสิทธิ → ปิดบัญชี → เข้ารอบ → ส่งเบิก ถ้าข้ามขั้นใดขั้นหนึ่ง รายการจะหายจากรอบโดยไม่มี error แจ้ง

2. แก้ยอดหลังปิดบัญชีไม่ได้

ต้องยกเลิกการปิดบัญชี (Cancel Close Account) ก่อน และทำได้เฉพาะก่อนส่งเบิกออกไป

3. Authen Code ขาด = เคลมไม่ผ่าน

ตรวจหน้า “ตรวจสอบการขอ Authen Code” ก่อนปิดรอบทุกครั้ง

4. รอบอุทธรณ์ต้องเลือกประเภทให้ถูก

Normal vs Appeal (และเวอร์ชัน Disabled) นำเข้าผิดประเภทจะจับคู่ไม่ตรง

5. Batch เงียบเมื่อ config ไม่ตรง

ดูกล่องเตือนในหัวข้อ Batch — ตรวจ Cron กับ JobList ให้ตรงกัน

6. รายการที่ Failed ไม่ retry เอง

ต้องกด “ส่งจองเคลมใหม่” หรือเรียก FetchSendMophClaimByMophClaimId ด้วยตัวเอง
