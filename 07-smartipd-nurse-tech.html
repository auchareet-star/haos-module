ขั้นที่ 1 — เริ่มกะ

  1. Login + เลือก Ward

    /auth/login → /auth/ward-selection — ระบบจำ Ward ที่เลือกล่าสุดไว้ให้

  2. ดูภาพรวมงานประจำวัน

    /patients/daily-overview · WardDailyOverviewComponent · API GET /api/OrderPlan/ward-daily-overview

    สรุปงานทั้ง Ward ในวันนั้น — กิจกรรมที่ต้องทำ, จำนวนที่ทำแล้ว/ค้าง แยกตามช่วงเวลา

  3. เปิด Work List

    /patients/work-list — รายการงานที่ต้องทำ รวมข้ามผู้ป่วย เรียงตามเวลา

  4. เข้าผู้ป่วยรายคน

    จาก /patients หรือสแกน QR ที่ป้ายข้อมือ (/patients/scan-qr) → เข้าหน้า /patients/admission/:an

ขั้นที่ 2 — บันทึกรับผู้ป่วยใน (IPD Admission Record)

/patients/admission/:an/ipd-admission-record · Permission NURSE + NURSE_VIEW_PHYSICAL_EXAMINATION

(มีอีกหน้าหนึ่งชื่อ …/physical-examination ที่ใช้ชื่อหัวข้อเดียวกัน)

เป็นแบบฟอร์มรับใหม่ที่ยาวและมีฟิลด์แบบมีเงื่อนไข (conditional field) จำนวนมาก ระบบจึงออกแบบให้ config แยกไว้ที่ admission-record-conditional-fields.config.ts

ตัวอย่างฟิลด์แบบมีเงื่อนไข

คำถามตัวเลือกฟิลด์ที่เปิดตามมา
รับผู้ป่วยจาก (receiveFromCode)REFERreceiveFromHospital — ระบุโรงพยาบาล (บังคับ)
OTHERreceiveFromOtherText — ระบุ (บังคับ)
มาถึงหอผู้ป่วยโดย (arriveByCode)SENDERsenderName — ชื่อผู้นำส่ง (บังคับ)

ชุด Enum ที่ backend เปิดให้ดึง

GET /api/IpdAdmissionRecord/enums/{enumType} และ endpoint เฉพาะทาง เช่น

  • allergy-category-codes · arrive-by-codes · chief-complaint-type-codes
  • contact-types · family-history-codes · gender-identity-codes
  • house-structure-codes · housing-type-codes · living-with-codes
  • job-duration-codes · occupation-type-codes
ข้อควรทราบสำหรับผู้ดูแลระบบ

ค่า enum ในไฟล์ config ฝั่ง frontend ต้องตรงกับ enum ฝั่ง backend (eIpdAdmissionRecord.cs ของ HA.OS) ถ้าฝั่งใดฝั่งหนึ่งเปลี่ยนชื่อค่า ฟิลด์เงื่อนไขจะไม่แสดง — ในไฟล์ config มีคำเตือนนี้กำกับไว้ชัดเจน

ขั้นที่ 4 — Order Plan (แผนการปฏิบัติ)

/patients/admission/:an/order-plan · Permission NURSE + ORDER_PLAN · OrderPlanController

Order Plan คือการแปลง Order ของแพทย์ให้กลายเป็น กิจกรรมที่มีเวลา (schedule) ให้พยาบาลทำตาม — เป็นตัวป้อนข้อมูลให้ทั้ง Work List, Daily Overview และ eMAR

  1. ระบบสร้างตารางกิจกรรม

    Job GenerateOrderPlanScheduleJob ฝั่ง HA.OS (รันเที่ยงคืน) สร้างตารางของวันถัดไป · ดูตารางได้ที่ GET /api/OrderPlan/schedules

  2. กรองดูกิจกรรม

    POST /api/OrderPlan/filter — กรองตามช่วงเวลา/ประเภท/สถานะ

  3. บันทึกการทำกิจกรรม

    POST /api/OrderPlan/activities — ระบุว่าทำแล้ว พร้อมเวลา/ผู้ทำ/หมายเหตุ

  4. เพิ่มกิจกรรมนอกแผน

    POST /api/OrderPlan/on-demand-activity — งานที่เกิดขึ้นเฉพาะหน้า

  5. ยืนยันด้วยพยาน (Witness)

    POST /api/OrderPlan/verify-witness — สำหรับกิจกรรมที่ต้องมีพยาบาลคนที่ 2 ยืนยัน (เช่น ยา High Alert)

  6. ตรวจเวลาชดเชย

    GET /api/OrderPlan/{orderPlanId}/compensatory-time — กรณีทำกิจกรรมช้ากว่ากำหนด

  7. ลบกิจกรรม

    DELETE /api/OrderPlan/activities/{activityId}

ขั้นที่ 5 — eMAR (Electronic Medication Administration Record)

/patients/admission/:an/emar · Permission NURSE + EMAR · MedicationDispensingController

ตาราง eMAR แสดง ยา × ช่วงเวลา โดยแต่ละช่อง (slot) มีสถานะของตัวเอง

สถานะ slotความหมายการกระทำ
pendingถึงเวลาแล้ว รอให้ยากดเพื่อเปิด modal ให้ยา / งดยา
overdueเลยเวลาที่กำหนดยังให้ยาได้ แต่ถูกทำเครื่องหมายว่าเลยเวลา
givenให้ยาแล้วบันทึกผู้ให้ + เวลา
withheldงดยาต้องระบุเหตุผล

ธงพิเศษที่ทับสถานะปกติ

ธงที่มาผลบนหน้าจอ
OFFแพทย์สั่งหยุดยา (TB_IPD_ORDER_NOTE_DETAILS) slot ที่ยัง pending/overdue จะแสดง badge OFF แทน — ห้ามให้ยา
HOLDแพทย์สั่งพักยา (TB_IPD_ORDER_HOLD_LOGS) แสดง badge HOLD พร้อมเหตุผล

Flow การให้ยา 1 slot

  1. เปิด eMAR ของผู้ป่วย

    GET /api/MedicationDispensing/patients

  2. กรองสถานะ

    ชิปด้านบน: all / pending / given / withheld / off / hold พร้อมตัวนับ

  3. ตรวจสอบ 5R ที่เตียง

    ผู้ป่วยถูกคน (สแกน QR ได้) · ยาถูกตัว · ขนาดถูก · เวลาถูก · วิถีทางถูก

  4. กดที่ slot

    เปิด emar-give-medication-modal (ให้ยา) หรือ emar-skip-medication-modal (งดยา)

  5. ยืนยัน

    POST /api/MedicationDispensing/dispense — บันทึกผู้ให้ยา เวลา และเหตุผลกรณีงดยา

ยา OFF / HOLD

ถ้าเห็น badge OFF หรือ HOLD ให้หยุดและตรวจสอบกับแพทย์/เภสัชกรก่อน ฝั่งเภสัชกรมีขั้นตอน “รับทราบ” (acknowledge) แยกต่างหาก (POST /api/PharmacistDispensing/acknowledge-off / acknowledge-hold) — ดู โมดูล 07

ข้อควรระวัง

1. eMAR ไม่ได้บล็อกยา OFF/HOLD อัตโนมัติ

หน้าจอแสดง badge เตือน แต่การตัดสินใจอยู่ที่พยาบาล — ต้องอ่าน badge ทุกครั้งก่อนให้ยา

2. Order Plan สร้างล่วงหน้าโดย Batch

ถ้า Job GenerateOrderPlanScheduleJob ไม่รัน ตารางกิจกรรมของวันจะว่าง — ให้ใช้ On-demand Activity ชั่วคราว และแจ้ง IT

3. ฟิลด์เงื่อนไขในแบบฟอร์มรับใหม่

ถ้าเลือกตัวเลือกแล้วช่อง “ระบุ” ไม่เปิด/ไม่บังคับ แสดงว่าค่า enum frontend-backend ไม่ตรง — เป็นปัญหา config ไม่ใช่ผู้ใช้

4. Ward ผิด = ไม่เห็นผู้ป่วย

รายการผู้ป่วยและ Daily Overview กรองด้วย Ward ที่เลือกไว้เสมอ

5. Permission ต้องครบทั้งคู่

route data ระบุ 2 permission เช่น ['NURSE','EMAR'] — ต้องมีครบตามที่ guard กำหนด ไม่งั้นจะถูกเด้งออกจากหน้า

6. บันทึกค่าใช้จ่ายที่ Ward ไปเข้าการเงินทันที

รายการที่บันทึกผ่าน other-expenses สร้าง TB_FINANCES จริง และจะไปโผล่ในสรุปค่ารักษาของงานการเงิน (โมดูล 02)
